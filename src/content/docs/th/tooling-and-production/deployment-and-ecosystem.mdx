## production build

`astro build` สร้าง output ที่ deploy ได้ใน `dist/` สิ่งที่อยู่ในนั้นขึ้นกับ rendering mode:

- **Static** — `dist/` เป็นโฟลเดอร์ของไฟล์ `.html`, CSS และ island JavaScript เป็นแค่ไฟล์
- **On-demand / hybrid** — `dist/` มี **server entry** ในรูปแบบที่ adapter ของคุณ target ด้วย (Cloudflare Worker, Node server, serverless function) พร้อม static asset

ต่อ type-checking เข้ากับ build เพื่อให้ type error หยุด deploy ที่ไม่ดี: `astro check && astro build`

## deploy สองแบบ

การตัดสินใจ deploy ที่ใหญ่ที่สุดคือ static vs on-demand — ตัวเลือกนี้กำหนดว่าคุณ host *ที่ไหน* ได้:

| | Static | On-demand (SSR) |
|---|--------|-----------------|
| Output | ไฟล์ HTML | server entry + assets |
| ต้องการ | static host / CDN อะไรก็ได้ | runtime (ผ่าน adapter) |
| Host | Cloudflare Pages, Netlify, GitHub Pages, S3, CDN อะไรก็ได้ | Cloudflare Workers, Node server, Vercel, Netlify Functions |
| เหมาะกับ | content ที่เหมือนกันสำหรับทุกคน | ข้อมูลต่อ request: auth, form, live data |
| Adapter | ไม่ต้อง | **ต้อง** |

เว็บ static ล้วน deploy ที่ไหนก็ได้ที่ serve ไฟล์ พอมี route ไหนเป็น on-demand (หรือใช้ server island หรือ Actions) คุณต้องตั้ง **adapter** ที่ตรงกัน — deploy โดยไม่มี adapter ก็เจอ error คลาสสิก "an adapter is required"

## ตั้ง site และ base ให้ถูก

สอง config value ที่มักทำคนสะดุดตอน deploy:

- **`site`** ต้องเป็น URL ที่ deploy จริง (เช่น `https://example.com`) sitemap, canonical tag และ RSS สร้าง absolute URL จากค่านี้ — `site` ผิด link ก็ผิด
- **`base`** ต้องตรงกับ subpath ที่คุณถูก serve deploy ไป `example.com/docs/` ก็ตั้ง `base: '/docs'` แล้วอ้าง internal link ด้วย base prefix serve ที่ domain root ก็ละไว้ `base` ที่ไม่ตรงเป็นสาเหตุปกติของ "CSS และ link ของเว็บที่ deploy 404 หมด" — asset ถูกหาที่ path ผิด

## ecosystem

Astro เป็น content-first และ ecosystem ของตัวเองสะท้อนสิ่งนั้น:

- **Starlight** — documentation-site framework ทางการที่สร้างบน Astro (คอร์สนี้ก็สร้างด้วย Starlight): sidebar, search, i18n และ dark mode มาในตัว
- **Integrations directory** — catalog ขนาดใหญ่ของ integration ทางการและ community: UI framework, CMS connector, image service, analytics และ adapter สำหรับ host หลักทุกตัว (มี package ทางการหนึ่งตัวที่หายไปใน Astro 7: `@astrojs/db` ไม่ได้ดูแลต่อแล้ว — ใช้ `node:sqlite`, Drizzle หรือ database แบบ hosted แทน)
- **content-focused patterns** — เมื่อรวมกับ content collection Astro เป็นตัวเลือกที่เหมาะสำหรับ blog, docs, marketing site และ headless-CMS front-end ที่คุณได้เว็บ static (หรือ hybrid) ที่เร็วพร้อม content ที่มี type

หยิบ framework อย่าง **Starlight** เมื่อตรงกับ use case ของคุณ แทนที่จะสร้าง docs infrastructure ใหม่ด้วยมือ — สัญชาตญาณ "compose อย่าสร้างใหม่" เดียวกันที่ไหลผ่าน Astro

## อัปเกรดจาก Astro 6 เป็น 7

โปรเจกต์ส่วนใหญ่อัปเกรดได้ในบ่ายเดียว checklist มีดังนี้:

1. **Node 22.12+** เป็นขั้นต่ำ (เท่ากับ Astro 6) รัน `npx @astrojs/upgrade` เพื่อ bump `astro` และ integration `@astrojs/*` ทุกตัวพร้อมกัน
2. **ถอด experimental flag ที่ stable แล้ว**: `experimental.cache`, `experimental.routeRules`, `experimental.logger` ย้ายไปเป็น `cache`, `routeRules`, `logger` ระดับบนสุด ส่วน `experimental.rustCompiler`, `queuedRendering`, `advancedRouting` ลบทิ้ง (เป็น default แล้ว)
3. **แก้สิ่งที่ Rust compiler ปฏิเสธ**: tag ที่ไม่ปิดและการซ้อนที่ผิดเป็น build error แล้ว error message ชี้ไฟล์และบรรทัดให้
4. **เช็ก whitespace**: `compressHTML` default เป็น `'jsx'` ใส่ `{" "}` ตรงที่ inline element ต้องมีช่องว่าง หรือตั้ง `compressHTML: true` ชั่วคราว
5. **Markdown plugin**: ถ้าใช้ remark/rehype plugin ให้ติดตั้ง `@astrojs/markdown-remark` และตั้ง `markdown: { processor: unified() }` ถ้าไม่ใช้ก็รับความเร็วของ Sätteri ไปเลย
6. **Vite 8**: ทบทวน migration note ของ Vite 8 สำหรับ plugin เฉพาะของ Vite ที่ตั้งไว้ใต้ key `vite`
7. **เปลี่ยนชื่อ `src/fetch.ts`** ถ้าคุณมีไฟล์ชื่อนี้ที่ไม่เกี่ยวกัน (หรือตั้ง `fetchFile`)
8. **API ที่ถูกถอด**: `@astrojs/db` (เปลี่ยนไป `node:sqlite`, Drizzle หรือ DB แบบ hosted), ค่าคงที่ event ของ `astro:transitions` (ใช้ชื่อ event แบบ string เช่น `'astro:before-preparation'`) และ `getContainerRenderer` ตอนนี้ import จาก `@astrojs/react/container-renderer`

จากนั้น `astro check && astro build` — build เร็วขึ้นอย่างเห็นได้ชัด ซึ่งคือรางวัล
