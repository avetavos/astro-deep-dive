ศัพท์ของ Astro เน้นที่ island เป็นหลัก — หน้าเว็บ render ออกมาเป็น static HTML เป็นค่า default และมีแค่ส่วนที่เราติด client directive ไว้ (หรือเลือกให้เป็น server island) เท่านั้นที่จะส่ง หรือรัน JavaScript จริง ๆ ทับซ้อนกันอยู่บนนี้ก็คือ content layer (collection ที่สร้างจาก loader แล้ว validate ด้วย schema แบบ Zod), Actions สำหรับเรียก server แบบ type-safe และ `<ClientRouter />` สำหรับ navigate แบบมี animation ระหว่างหน้าเดิม เวลาอ่านบทเรียนแล้วเจอคำที่ไม่คุ้น หรือไม่แน่ใจว่ายังใช้ได้อยู่กับ Astro 7.3.5 ไหม ให้กลับมาดูที่นี่

## A

| Term | ความหมาย | บทเรียน |
|------|---------|--------|
| action / `defineAction()` | function ฝั่ง server แบบ type-safe ของ Astro: ประกาศด้วย `defineAction({ input, handler })` ใน `src/actions/` แล้วเรียกจาก client ผ่าน object `actions` ที่ generate ให้ พร้อม validate ด้วย Zod อัตโนมัติและได้ผลลัพธ์ที่มี type — ไม่ต้องเขียน `fetch()`/URL/JSON เองด้วยมือ | [Actions](/astro/th/server-side/actions/) |

| `astro check` | คำสั่ง CLI (ใช้ `@astrojs/check` + TypeScript ข้างใน) ที่ type-check ไฟล์ `.astro` แบบครบวงจร รวมถึง expression ข้างใน template ด้วย จับ prop type ที่ผิดที่ `tsc` ธรรมดารันแค่ frontmatter อย่างเดียวจะพลาดไปได้ | [Testing & Tooling](/astro/th/tooling-and-production/testing-and-tooling/) |
| `astro sync` | สร้าง (หรือสร้างใหม่) type ของ TypeScript สำหรับ content collection และ virtual module `astro:` อื่น ๆ ลงใน `.astro/` type พวกนี้ regenerate ตอน `astro dev`/`astro build` อยู่แล้ว แต่ `sync` เฉย ๆ คือทางลัดที่เร็วกว่าทันทีหลังแก้ schema | [TypeScript & Content Types](/astro/th/tooling-and-production/typescript-and-content-types/) |
| `astro-island` | custom element ที่ client runtime ของ Astro ห่อรอบ component ที่ hydrate แล้วใน HTML ที่ render ออกมา พกพา client directive, prop ที่ serialize แล้ว และข้อมูล renderer ที่ต้องใช้ hydrate มันในเบราว์เซอร์ | [Client Directives](/astro/th/islands/client-directives/) |
| `astro:env` | module สำหรับ environment variable แบบมี type: ประกาศตัวแปรครั้งเดียวใน `env.schema` ของ `astro.config.mjs` แล้ว import จาก `astro:env/client` หรือ `astro:env/server` ได้ type จริง ๆ แทนที่จะเป็น string ไม่มี type แบบ `process.env` | [Config & Integrations](/astro/th/tooling-and-production/config-and-integrations/) |
| `Astro.glob()` (removed) | วิธีเดิมในการ import ไฟล์ในเครื่องหลายไฟล์แบบ eager จาก frontmatter (`await Astro.glob('./posts/*.md')`) เอาออกไปใน Astro v5 แทนที่ด้วย `import.meta.glob(pattern, { eager: true })` ของ Vite เอง ซึ่งไม่คืน `Promise` และไม่ต้องใช้ `await` | [Data Fetching](/astro/th/content-and-data/data-fetching/) |
| `@astrojs/db` (removed) | integration ฐานข้อมูลแบบ built-in ของ Astro ที่ใช้ Drizzle เบื้องหลัง ถูกเอาออกทั้งหมดใน Astro 7.0 โดยไม่มี package ทดแทนที่ทีมหลักดูแลต่อ — ให้ย้ายไปใช้ `node:sqlite` ของ Node ที่ built-in, Drizzle ORM ตรง ๆ หรือ library ฐานข้อมูลอื่น | [Deployment & Ecosystem](/astro/th/tooling-and-production/deployment-and-ecosystem/) |

## C

| Term | ความหมาย | บทเรียน |
|------|---------|--------|
| `class:list` | attribute directive ที่รับ array ของ string, object และ array ซ้อนกันได้ (`class:list={['box', { red: isRed }]}`) แล้ว merge ออกมาเป็น string `class` เดียว — เป็น helper แบบ built-in ของ Astro ที่เทียบเท่า `clsx` ยอดนิยม | [Styles & Scripts](/astro/th/components/styles-and-scripts/) |
| client directive | กลุ่ม attribute `client:*` (`client:load`, `client:idle`, `client:visible`, `client:media`, `client:only`) ที่เลือกให้ component ของ framework ส่ง JavaScript และ hydrate ในเบราว์เซอร์ — ถ้าไม่ใส่ component นั้นจะ render เป็น static HTML เฉย ๆ | [Client Directives](/astro/th/islands/client-directives/) |
| `client:load` | hydrate JavaScript ของ component ทันทีที่หน้าโหลดเสร็จ — directive สำหรับสิ่งที่ต้อง interactive ทันที (nav menu, ปุ่มเปิด modal) | [Client Directives](/astro/th/islands/client-directives/) |
| `client:idle` | hydrate หลังจากหน้าโหลดครั้งแรกเสร็จและ `requestIdleCallback` ของเบราว์เซอร์ทำงานแล้ว ถ้าเบราว์เซอร์ไม่มี `requestIdleCallback` ก็จะ fallback ไปใช้ event `load` แทน — เหมาะกับสิ่งที่ interactive ได้แต่ไม่เร่งด่วน | [Client Directives](/astro/th/islands/client-directives/) |
| `client:visible` | hydrate ทันทีที่ component เลื่อนเข้ามาอยู่ใน viewport (ผ่าน `IntersectionObserver`) — ตัวเลือก default สำหรับอะไรก็ตามที่อยู่ใต้ fold ที่ไม่จำเป็นต้อง interactive ก่อนที่ผู้ชมจะเห็นมัน | [Client Directives](/astro/th/islands/client-directives/) |
| `client:media` | hydrate ก็ต่อเมื่อ CSS media query ที่กำหนดตรงกัน (`client:media="(max-width: 640px)"`) — สำหรับ component ที่ interactive หรือมีอยู่จริง เฉพาะบางขนาด viewport เท่านั้น | [Client Directives](/astro/th/islands/client-directives/) |
| `client:only` | ข้าม server render ไปเลย แล้ว render เฉพาะฝั่งเบราว์เซอร์เท่านั้น ต้องระบุชื่อ framework เป็น string ด้วย (`client:only="svelte"`) เพราะ Astro ไม่มี markup ที่ render จาก server ให้รู้ว่าต้อง hydrate ด้วย renderer ตัวไหน | [Client Directives](/astro/th/islands/client-directives/) |
| `ClientRouter` | component จาก `astro:transitions` (`<ClientRouter />` วางใน `<head>`) ที่ดักการ navigate ไปหน้าเดิม (same-origin) สลับ DOM ให้ แล้วขับเคลื่อน animation ของ transition — เป็นชื่อ export ปัจจุบันของ router สำหรับ view transitions ของ Astro | [View Transitions](/astro/th/rendering-and-performance/view-transitions/) |
| component | ไฟล์ `.astro`: component script (ส่วน frontmatter ที่ล้อมด้วย fence) ตามด้วย template — หน่วยพื้นฐานของ Astro ใช้เดี่ยว ๆ ได้หรือประกอบเป็นหน้าก็ได้ | [The Component Model](/astro/th/foundations/the-component-model/) |
| content collection | ชุดข้อมูล content แบบ type-safe ที่ config ไว้ใน `src/content.config.ts` ด้วย loader และ schema ทางเลือก แล้ว query ผ่าน `getCollection()`/`getEntry()` ของ `astro:content` ได้ผลลัพธ์มี type ครบ | [Content Collections](/astro/th/content-and-data/content-collections/) |
| content layer | สถาปัตยกรรมเบื้องหลัง content collection ตั้งแต่ Astro v5: collection ถูกกำหนดด้วย *loader* แทนที่จะเป็น directory ตายตัวอย่าง `src/content/<name>/` รวม Markdown/MDX/JSON ในเครื่องกับข้อมูลจากระยะไกลหรือแบบ live ให้อยู่ใต้ API `getCollection()` เดียวกัน | [Content Collections](/astro/th/content-and-data/content-collections/) |
| Container API | `experimental_AstroContainer` (จาก `astro/container`) — render component ของ Astro หรือ framework ตัวเดียวออกมาเป็น string HTML นอกกระบวนการ build หน้าทั้งหน้า เป็นเครื่องมือที่ test fence ของคอร์สนี้เองใช้ตรวจสอบ markup ที่ render ออกมา | [Testing & Tooling](/astro/th/tooling-and-production/testing-and-tooling/) |
| `context.locals` | object ต่อ request ที่ middleware เติมค่าให้ (`context.locals.user = ...`) ให้โค้ดที่เทียบเท่า `load`, action และ endpoint ที่อยู่ถัดไปอ่านได้ ตั้งแต่ Astro v5 การเพิ่มค่าเข้าไปต้องใช้ `Object.assign(context.locals, {...})` แทนที่จะเขียนทับทั้ง object | [Middleware & Sessions](/astro/th/server-side/middleware-and-sessions/) |

| endpoint / API route | ไฟล์ `src/pages/*.ts` ที่ export function ตาม HTTP method (`GET`, `POST`, …) แล้วคืน `Response` ตรง ๆ — เป็นทางเลือกระดับล่างกว่าที่ไม่ผูกกับ framework ใดโดยเฉพาะ สำหรับสร้าง API ที่ client ที่ไม่ใช่ Astro ก็เรียกได้ แทนที่จะใช้ Actions | [Endpoints & API Routes](/astro/th/server-side/endpoints-and-api-routes/) |
| `envField()` | helper ที่ import จาก `astro/config` ใช้ข้างใน `env.schema` เพื่อประกาศ type, context (`'client'`/`'server'`) และระดับการเข้าถึง (`'public'`/`'secret'`) ของตัวแปร environment แต่ละตัว เช่น `envField.string({ context: 'server', access: 'secret' })` | [Config & Integrations](/astro/th/tooling-and-production/config-and-integrations/) |

## O–P

| Term | ความหมาย | บทเรียน |
|------|---------|--------|
| on-demand rendering | การ render route ต่อ request ตอน runtime แทนที่จะ render ตอน build time — เป็นค่า default ของทุก route ภายใต้ `output: 'server'` และเลือกใช้เฉพาะ route ได้ภายใต้ `output: 'static'` ผ่าน `export const prerender = false` (ซึ่งต้องมี adapter ตามมาด้วย) | [Rendering & Output Modes](/astro/th/foundations/rendering-and-output-modes/) |
| output: static | output mode แบบ default: ทุก route ที่ไม่ได้ตั้ง `prerender = false` จะถูก build เป็นไฟล์ static HTML ตอน build time deploy ไปที่ static host ไหนก็ได้โดยไม่ต้องมี server runtime | [Rendering & Output Modes](/astro/th/foundations/rendering-and-output-modes/) |
| output: server | ทุก route render แบบ on-demand ตอน request เป็นค่า default (แต่ละ route ก็ยังเลือกกลับไปเป็น `prerender = true` ได้) ต้องมี adapter ของ platform ที่ server จะรันจริง ๆ | [Rendering & Output Modes](/astro/th/foundations/rendering-and-output-modes/) |

| `<Picture>` | component ของ `astro:assets` ที่ output element `<picture>` พร้อม `<source>` หลายแบบทั้ง format และขนาด สำหรับความต้องการแบบ art-direction หรือ format-fallback ที่มากกว่าที่ `<Image>` เดี่ยว ๆ ครอบคลุมได้ | [Images & Assets](/astro/th/rendering-and-performance/images-and-assets/) |
| prefetch | การ prefetch link แบบ built-in ของ Astro (config ผ่าน key `prefetch` ระดับบนสุด กลยุทธ์ default คือ `hover`) ที่ดึง HTML ของหน้าที่ link ไว้มาล่วงหน้าก่อนจะ navigate จริง ให้รู้สึกเหมือนโหลดทันที | [View Transitions](/astro/th/rendering-and-performance/view-transitions/) |
| prerender | `export const prerender = true` (ใน `output: 'server'`) หรือ `= false` (ใน `output: 'static'`) พลิกโหมด render ของ route นั้นให้ตรงข้ามกับค่า default ระดับ output — เป็น override รายตัวสำหรับตอนที่เว็บส่วนใหญ่เป็น static (หรือ on-demand) แต่มี route เดียวที่ต้องการตรงข้าม | [Rendering & Output Modes](/astro/th/foundations/rendering-and-output-modes/) |

| Rust compiler | Astro 7.0 เปลี่ยน compiler ของ `.astro` จากที่เขียนด้วย Go ตัวเดิม มาเป็นตัวใหม่ที่เขียนด้วย Rust: เร็วขึ้น แต่ก็เข้มงวดขึ้นด้วย — แท็กที่ไม่ปิดกลายเป็น compile error จริง ๆ แล้ว และ HTML ที่ผิดจะไม่ถูกแก้ให้เงียบ ๆ แบบที่ compiler ตัวเก่าเคยทำ | [Testing & Tooling](/astro/th/tooling-and-production/testing-and-tooling/) |
